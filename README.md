# سايبر مكة — موقع الحجز + تطبيق الأدمن

مشروع منفصل تمامًا عن ليلتنا: قاعدة بيانات ومفاتيح وحاوية Docker لوحدهم. الحاجة الوحيدة المشتركة هي إن Caddy
بتاع سيرفر ليلتنا هو اللي بيعمل HTTPS للدومين بتاع سايبر مكة.

| الجزء | فين | إيه |
|---|---|---|
| الموقع | `web/` | HTML + JS عادي (من غير build). الحجز من غير حساب، ومتابعة الطلب بلينك سري |
| السيرفر | `server/` | Supabase خفيف (Postgres + Auth + REST + Storage)، و`sql/` و`scripts/` |
| تطبيق الأدمن | `app/` | Flutter (ويندوز + أندرويد). الأندرويد بيتنزل APK مباشر، **مش على Google Play** |

## دورة الحجز

1. العميل يختار الفرع (فلمنج / شارع 20) ← أجهزة PC أو غرفة بلايستيشن ← العدد والمدة ← اليوم والساعة ← اسمه وموبايله.
2. الطلب بيوصل للأدمن فورًا: رنة الطلب الجديد مرة واحدة افتراضيًا، ورنة تحويل الـ deposit بتتكرر 30 ثانية افتراضيًا؛
   الاتنين قابلين للتعديل من إعدادات الأدمن. الإشعار يفضل ظاهر لحد ما حد يتعامل مع الطلب.
3. لو اتقبل، العميل بيشوف مبلغ العربون وبيانات InstaPay/Telda ومهلة الدفع (15 دقيقة افتراضي).
4. التأكيد بيحصل بطريقة من دول:
   - **تلقائي**: موبايل المحل بيقرا إشعار InstaPay/Telda أو رسالة البنك، والمبلغ بيطابق العربون بالظبط.
   - **يدوي**: الأدمن يدوس «الفلوس وصلت». ده لو مفيش شبكة، أو الإشعار ماوصلش، أو التحويل اتعمل بطريقة تانية.
5. الحجز يبقى «متأكد». العميل يعرض كود الحجز في الفرع، والعربون بيتخصم من حسابه.

لو المحل ماردّش في مهلة الرد، أو العميل ماحوّلش في مهلة الدفع، الطلب بينتهي لوحده والمكان بيفضى.

## الحماية من النصب في التأكيد التلقائي

- **الإشعارات** بتتقري من التطبيقات اللي في القايمة بس (اسم الباكدج، زي `com.egyptianbanks.instapay`). أي تطبيق
  تاني مايقدرش يعمل إشعار باسم الباكدج ده.
- **الـ SMS** بتتقري بس من **اسم شركة** موجود في القايمة (InstaPay, CIB, NBE …). أي رسالة جاية من رقم موبايل بتتجاهل
  خالص، والسيرفر بيرفضها هو كمان.
- التحويل لازم يكون **وارد** (فيه «استلام / إيداع / إضافة»). أي خصم أو دفع بيتجاهل.
- **المبلغ لازم يطابق بالظبط** عربون حجز مستني، ويكون وصل بعد الموافقة. لو فيه حجزين مستنيين نفس المبلغ، التاني بيدفع
  جنيه زيادة (بيتخصم من حسابه). وده اللي بيخلّي الربط التلقائي يعرف كل تحويل تبع أنهي حجز.
- لو فيه أي لخبطة، التحويل بيستنى في شاشة «التحويلات» والأدمن يربطه بإيده.
- لو موبايل المحل مفيهوش نت، التحويلات بتتخزن عليه وبتتبعت أول ما النت يرجع.

## التركيب على السيرفر (مرة واحدة)

1. **الدومين**: من هوستنجر اختار الدومين المجاني. في الـ DNS اعمل 3 سجلات `A`، وكلهم بيشاوروا على IP سيرفر ليلتنا
   `187.7.77.218`: `@` و`api` و`www`.
2. **ارفع الفولدر للسيرفر** (من الكمبيوتر):
   ```
   scp -r cyber_maka admin@187.7.77.218:~/
   ```
3. **ركّب** (على السيرفر):
   ```
   cd ~/cyber_maka && DOMAIN=الدومين.com sh server/scripts/install.sh
   ```
   السكربت بيعمل مفاتيح جديدة في `/opt/maka/.env` (احفظ نسخة في Bitwarden)، ويشغّل قاعدة البيانات، ويضيف سطر
   `import` واحد في آخر Caddyfile بتاع ليلتنا، وبياخد نسخة احتياطي منه قبلها. وكمان بيعمل backup يومي الساعة 3:40.
   في الآخر بيطبع `kApiUrl` و`kAnonKey`.
4. **حساب الأدمن**:
   ```
   sh server/scripts/create_admin.sh الإيميل "اسم صاحبك"
   ```
   وبعد كده أي أدمن يقدر يضيف الباقي من جوه التطبيق نفسه: **الإعدادات ← الفريق ← أدمن جديد**.
   كل حساب جديد بيدخل بكلمة سر مؤقتة (بتحددها وقت الإنشاء) وبيضطر يغيّرها أول دخول.
   ومن نفس الشاشة: إعادة كلمة سر أي أدمن تاني (بيقفل جلساته القديمة)، أو مسح حسابه خالص.
   آخر أدمن مينفعش يتمسح، ومسح أدمن بيوقف كمان أي موبايل مسجّل بيه (الرنة وقراية التحويلات).
    لو السيرفر متسطّب من قبل التحديث ده: شغّل `sh server/scripts/apply_sql.sh` من فولدر المشروع
    (بيعيد تطبيق `sql/*.sql` ويحدّث كاش PostgREST — نفس اللي `install.sh` بيعمله دلوقتي، بس من غير باقي الخطوات).
5. **التطبيق**: حط القيمتين في `app/lib/config.dart` (أو مرّرهم بـ `--dart-define`) وابني:
   ```
   cd app
   flutter build apk --release      # build/app/outputs/flutter-apk/app-release.apk
   flutter build windows --release  # build/windows/x64/runner/Release/
   ```
   من **الإعدادات ← رنة إشعارات الأدمن** تقدر ترفع رنة مختلفة لكل نوع (MP3/WAV/OGG/M4A/AAC، بحد أقصى 5 ميجا)،
   تسمع معاينة، وترجع للافتراضي، وتختار تشغيل مرة أو تكرار لمدة من 1 إلى 300 ثانية. الإعدادات عامة لكل أجهزة الأدمن.
   صور الفروع تحتفظ بنسخة غير مقصوصة منفصلة؛ تعديل القص يبدأ منها كل مرة، بدل ما يعيد قص النسخة السابقة.
   لتحديث سيرفر موجود بعد تنزيل التعديلات من GitHub، شغّل `sudo sh server/scripts/apply_sql.sh` من فولدر المشروع؛
   وبعدها ابنِ ووزّع نسخة التطبيق الجديدة على أجهزة الأدمن.
6. أي تعديل في الموقع بعد كده:
   ```
   sudo sh server/scripts/deploy_web.sh
   ```

## موبايل المحل (أندرويد) — أول مرة

1. نزّل الـ APK وثبّته، وسجّل دخول. الموبايل بيتسجل لوحده كجهاز للمحل وبيبدأ يرن مع أي طلب جديد.
2. من **الإعدادات ← الموبايل ده**:
   - اسمح بالإشعارات، واستثني التطبيق من توفير البطارية.
   - على الموبايل اللي عليه InstaPay/Telda بس: فعّل «قراية إشعارات التحويل» و«رسايل البنوك».
   - على أندرويد 13 وأعلى، التطبيقات اللي اتنزلت من برا المتجر الاختيار ده بيبقى رمادي فيها. الحل: **معلومات التطبيق ← ⋮ ← السماح بالإعدادات المحظورة**، وبعدها فعّله.
3. دوس **«جرّب الرنة»**.
4. أول تحويل حقيقي: لو اسم الباكدج أو اسم الراسل مختلف عن القايمة، الرسالة هتظهر تحت «رسايل فيها مبالغ اتجاهلت»
   ومعاها زرار **اعتمد**. ماتعتمدش غير البنوك والتطبيقات الحقيقية.

## التجربة المحلية

`server/docker-compose.yml` بيشتغل محليًا بـ `.env` تجريبي و`EDGE_NETWORK=maka-test-edge`، وCaddy محلي بيستخدم
`server/caddy/maka.caddy` (والدومين متغيّر لـ `:8088` و`:8089`). اتجرب كده: الحجز، والتعارض، والرفض، والقبول،
والعربون المميّز، والربط التلقائي بإشعار InstaPay، ورفض الـ SMS من رقم موبايل، والتأكيد اليدوي، وانتهاء المهلة،
والصلاحيات.
